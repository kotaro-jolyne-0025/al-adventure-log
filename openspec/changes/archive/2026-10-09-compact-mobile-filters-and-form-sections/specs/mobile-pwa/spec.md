# Spec Delta

## ADDED Requirements

### Requirement: Collapsible mobile inventory filters
寬度不超過 600 CSS 像素時，倉庫 SHALL 保留可見搜尋與篩選入口，篩選選項預設收合，入口 SHALL 顯示已選篩選條件數（不包含搜尋文字）。展開／收合 SHALL 保留既有搜尋及篩選條件；展開入口、篩選與清除篩選操作 SHALL 至少 44 CSS 像素高，支援鍵盤並有可見焦點。601 CSS 像素以上 SHALL 維持原有完整篩選排列及尺寸。

#### Scenario: 搜尋與收合篩選
- **WHEN** 玩家在手機倉庫搜尋、展開選擇稀有度或同調，再收合篩選
- **THEN** 搜尋可使用、清單保留篩選結果，入口顯示已選條件數，重新展開保留選取狀態

#### Scenario: 清除與鍵盤
- **WHEN** 玩家用 Enter／Space 展開並操作篩選，再清除篩選
- **THEN** 入口及選項焦點可見，依現有清除規則恢復清單與搜尋狀態，已選數歸零

### Requirement: Compact mobile optional adventure sections
寬度不超過 600 CSS 像素時，冒險表單的永久物品、消耗品、故事獎勵及休整活動，空白區塊 SHALL 只保留標題與新增入口，不提供展開／收合。已有明細的區塊 SHALL 預設展開並提供可辨識、支援鍵盤、至少 44 CSS 像素高的展開／收合入口。新增明細及提交驗證失敗時 SHALL 展開相關區塊；物品數量不符期間 SHALL 維持相關明細展開。基本資料、資源變化與結算 SHALL 持續可用。切換顯示與視窗尺寸 SHALL 保留輸入、資料、歷史快照及既有提交校驗。601 CSS 像素以上 SHALL 保留原有完整表單排列。

#### Scenario: 空白表單與新增明細
- **WHEN** 玩家在手機建立新冒險並加入選填明細
- **THEN** 空白區塊沒有展開／收合入口，加入明細後欄位自動顯示並提供切換，基本資料與結算維持可見

#### Scenario: 標題切換與筆數
- **WHEN** 玩家在手機查看已有明細的選填區塊並點擊標題區
- **THEN** 標題區以小箭頭表示展開狀態，顯示明細筆數，並支援鍵盤切換與可見焦點，不另顯示外框切換按鈕；新增入口獨立操作

#### Scenario: 收合後新增及移除明細
- **WHEN** 玩家收合已有明細的區塊後新增，或移除該區塊最後一筆明細
- **THEN** 新增時重新展開且保留原輸入；移除最後一筆後不顯示展開／收合入口

#### Scenario: 已有資料與數量錯誤
- **WHEN** 玩家編輯有明細的冒險，或提交時物品數量不符、名稱或活動描述空白
- **THEN** 已有資料預設展開且可收合；驗證失敗時相關明細自動展開，保留原錯誤提示並阻止提交，修正後依原規則儲存

#### Scenario: 手機與桌機切換
- **WHEN** 玩家在填寫途中切換 600px 以下與 601px 以上的視窗
- **THEN** 寬視窗顯示原有完整內容，輸入及選擇保持不變，回到手機沿用展開狀態與資料可見性
