# Spec Delta

## ADDED Requirements

### Requirement: Discoverable application updates

系統 SHALL 在應用程式啟動穩定後、頁面從背景返回及恢復連線時檢查新版，且同時進行的檢查 SHALL 不重複發送。所有頁面（包含未登入頁面）SHALL 在右上角選單提供目前執行中的產品版號與手動檢查入口，不常駐上方版本資訊列。選單 SHALL 顯示檢查中狀態；手動檢查 SHALL 以 Snackbar 回報沒有新版、離線及檢查失敗的結果，自動檢查無新版時不顯示提醒。

#### Scenario: 啟動及返回頁面
- **WHEN** 支援更新的應用程式啟動完成、從背景返回或恢復連線
- **THEN** 在可見頁面檢查更新；同一時間已有檢查時不重複發送

#### Scenario: 手動檢查與錯誤
- **WHEN** 玩家手動檢查更新，或在離線／檢查失敗的情況操作
- **THEN** 顯示符合結果的文字，不把失敗當成最新版；恢復連線後可重試

#### Scenario: 不支援更新的環境
- **WHEN** 更新服務未啟用
- **THEN** 選單仍顯示目前版本，檢查更新按鈕停用，不發送更新請求

### Requirement: Persistent safe update action

新版下載完成或目前快取無法復原時，系統 SHALL 以既有上方 Snackbar 提醒並提供重新整理按鈕，且 SHALL 在右上角選單保留更新／重新載入入口。Snackbar 可自動結束或被一般操作提示取代；選單入口 SHALL 不因頁面切換、再次檢查或沒有其他新版而消失。系統 MUST NOT 自動重新整理或無重新載入地切換執行中版本。玩家選擇重新整理時 SHALL 提醒未儲存輸入會遺失，且只有確認後才重新載入。

#### Scenario: 新版可用且仍在編輯
- **WHEN** 玩家編輯表單時新版已準備好，並繼續操作或切換頁面
- **THEN** 上方出現更新提醒但不自行重新整理；即使提醒被其他操作取代，選單仍提供重新整理入口

#### Scenario: 取消或確認更新
- **WHEN** 玩家選擇重新整理，接著取消或確認提醒
- **THEN** 取消／Escape 保持表單與輸入；確認才重新載入且同時只開啟一個確認視窗

#### Scenario: 快取無法復原
- **WHEN** 目前執行的版本發生無法復原的快取錯誤
- **THEN** 顯示需重新載入的 Snackbar 並保留選單入口，仍由玩家確認後才重新載入

#### Scenario: 手機與放大文字
- **WHEN** 玩家在明暗主題、320／390／1280 CSS 像素寬與 200% 字級查看更新選單及提示
- **THEN** 文字及操作可換行且不水平溢出，按鈕至少 44 CSS 像素高且有可見鍵盤焦點

### Requirement: Revalidated update metadata

網站入口與版本更新中繼檔 SHALL 要求 HTTP 快取重新驗證；發現新版時 SHALL 保留離線快取能力，且不得為了更新清除使用者的登入狀態或資料。

#### Scenario: 發布新版本
- **WHEN** 已發布新的應用程式內容，瀏覽器重新請求入口或更新中繼檔
- **THEN** 回應要求快取重新驗證，更新流程不清除使用者資料
