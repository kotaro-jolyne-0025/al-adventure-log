# Design

## Context

參見 proposal.md。舊表單的升級區與活動清單各自編輯，活動描述包含天數，帳本則存該次休整期活動合計。已關閉 PR 使用另一次伺服器固定扣款，與可編輯預填的設計相衝。

## Decisions

### 表單與草稿

沿用已選的升級區排列及現有活動編輯欄位。玩家在升級區選迎頭趕上時預填一筆活動，未手動修改前才隨級數更新。設為 0 級時移除未修改的預填活動。修改或移除活動後保留玩家的決定，草稿須保存活動及其在本次編輯是否仍可自動更新。載入已儲存紀錄或舊草稿時保留原活動及天數。活動區的快捷選單移除迎頭趕上，保留其他預設和自訂活動。

### 入帳與詳情

請求與回應的 `downtimeDowntimeChange` 都表示全部休整期活動的實際合計。由正常活動流程計入預填列一次。後端沿用帳本、交易及原有檢查，`linkedCatchupCount` 只用於還原升級原因。舊用戶端也送完整合計。缺少級數欄位時，保留等級差相同的升級原因，等級差有變動則清除舊原因。詳情顯示已存級數，實際天數由既有休整期活動顯示。

修改以新舊貢獻差額更新角色。刪除沿用已保存的等級與休整期淨變動，與子項目及角色狀態在同一交易回沖。

### 舊紀錄及相容性

API 的級數由現有 `catchup_count` 儲存。讀取僅採用 0 至 19 且與該筆等級差相容的值。舊紀錄保留原活動和資源，沿用舊顯示值不會觸發預填。原本只有一筆迎頭趕上活動且已保存適用的正級數時，編輯表單可使用已入帳的天數補足活動內未填的天數。

此版沿用 V31 結構，沒有 migration 或舊資料批次回填。舊用戶端仍可使用完整合計與保存的活動。
