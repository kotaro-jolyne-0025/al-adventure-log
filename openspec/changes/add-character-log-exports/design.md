# Design

## Context

動機與範圍見 proposal.md，驗收契約見 `specs/adventure-export/spec.md`。

已確認的現況：

- `AdventureService.getAllByCharacter` 經記憶體快取讀列表，列表回應含休整活動與故事獎勵，但不含全部歷史物品；逐筆 `getDetails` 會產生 N+1，且多個 HTTP 回應不能保證同一資料庫快照。
- `AdventureEntryMapper.findListSnapshot` 已合併主表、活動、獎勵與所有權；`findDetailSnapshot` 另讀獲得物品、相鄰快照與舊倉庫。既有 LATERAL UNION ALL／result map 可避免不同子清單互乘。
- `AdventureEntryService` 已有歷史不連續判斷、資源與子項目 DTO 映射，應局部共用；不逐筆呼叫會查詢下一筆的版本。`AdventureGainedItemMapper` 目前只有依單筆冒險查詢。
- `LocalStore` 已提供 `sessionChanged`、`changes` 與 generation；角色服務有快取失效通知，列表有 `DestroyRef`。不需新增匯出快取或登入狀態系統。
- 前後端尚無 PDF／XLSX 產生套件；前端字型透過外部 CSS 載入，不能當成後端 PDF 已具備的字型資源。
- SRS 指定玩家名稱來自 `users.display_name`；現有角色 DTO 的 `playerName` 仍映射 `character.player_name`。匯出依 SRS 讀取同快照內帳號顯示名稱，不以舊角色欄位或 JWT 中可能過期的名稱替代；這次不擴大成整個角色 API 修正。

### 範本檢視記錄

使用者提供的「冒險紀錄表.pdf」SHA-256 為 `7f92c6298fa23f78ca2334a642b1f9552e0f039977e22c452c8d1c7fd3f5e3b9`，共兩頁，各為 630 × 810 pt、無旋轉，每頁三筆，132 個文字表單欄位皆未填值。兩頁視覺配置相同，可當作重複主表，而非固定要輸出兩頁的文件。

已逐頁渲染檢視。欄位有 `undefined` 等不具語意的名稱與各頁流水後綴，須以固定對照表及矩形校驗辨識用途。使用者已明確要求直接用原版 PDF、設計完全相同，因此將原稿作為固定範本資源，保留頁首舊季別說明及頁尾版權文字；靜態說明不成為新增業務規則。Poppler 渲染原檔曾回報 marked-content 語法警告，但兩頁均能正常顯示，已完成直接填寫原稿的樣張驗證。

原版填寫樣張使用第一頁的 66 個欄位，三筆含休整活動的虛構資料，第二筆備註 120 字、第三筆超量截尾。所有 Widget 均對應同一正規欄位樹中的實體，樣張保留欄位值與外觀；檢查原頁面內容串流不變，150 dpi 渲染後填寫欄位以外的畫素無差異。原始 PDF 雜湊不變；此為版型可行性驗證，不代表網站匯出功能已完成。

## Goals / Non-Goals

**Goals:** 讓一次匯出的全部資料來自同一快照，PDF 直接填寫原稿且保持原設計、固定欄位內截尾，XLSX 保留完整資訊並適合篩選與計算，不把檔案產生工作塞入資料庫交易。

**Non-Goals:** 單筆／日期區間／多角色選擇、匯入或還原、即時雲端試算表同步、背景工作佇列、匯出歷史、離線匯出、庫存盤點表、自訂範本／PDF 表單編輯器、重建或改版原稿、紙本完整明細附頁、正式發布與部署。

## Decisions

### 1. 一個受保護的檔案下載 API

新增 `GET /api/characters/{characterId}/exports?format=pdf|xlsx`，沿用 `@AuthenticationPrincipal` 與角色 owner-filtered 查詢。格式只接受兩個明確值；未指定／非法格式以 400 回既有 JSON 錯誤結構，角色不存在或不屬於登入者一律 404，未登入 401。已無冒險用既有 `BusinessException` 回 400「尚無冒險紀錄可匯出」。

回應為完整檔案，PDF 使用 `application/pdf`，XLSX 使用 `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`；`Content-Disposition: attachment` 由框架產生 UTF-8 安全檔名，並設 `Cache-Control: private, no-store`。檔名採 `冒險紀錄_<安全角色名稱>_<匯出日期>.<副檔名>`，去除控制字元、路徑及 header 特殊字元，空名稱回退固定名稱。前後端不得將 JSON 錯誤下載成檔案。

選擇同步下載是因為這是單角色資料的使用者操作；先不建背景工作、公開下載網址或檔案儲存服務。PDF 直接下載後以裝置既有 PDF 閱讀器預覽／列印，省去另一套 HTML 列印版與新增頁面。

### 2. 一次完整讀取，格式產生在交易外

建立一個匯出快照 DTO：匯出時間、必要角色／玩家顯示資料、已排序的冒險與完整子項目；排除帳號 Email、使用者／認證實體與頭像。以一個由 Spring proxy 呼叫的短暫唯讀 REPEATABLE READ 方法組裝 DTO，返回後由產生器處理檔案，不在自呼叫方法上放無效的交易註解。

沿用既有角色與列表查詢，再新增同角色歷史物品的批次查詢（SQL 連接所屬角色並限制 userId），需要時一次讀舊倉庫；帳號顯示名稱亦在同交易內讀取。以固定次數查詢組裝，而非每筆讀詳情或逐筆查下一筆。活動、獎勵與物品各依 `created_at, id` 穩定排序，主表依 `play_date ASC NULLS LAST, created_at, id`。

重用／局部提取既有 DTO 映射與接收已知下一筆紀錄的不連續判斷，在已排序清單上判斷警告；保留舊有呼叫端行為與測試，不建立通用匯出框架或將 entity 直接傳給 controller。缺少的必要清單與讀取錯誤不能轉成空清單。

替代方案為擴大既有列表 SQL，將角色、使用者與全部物品也合進單一 SELECT；暫不選擇，避免此次增加輸出格式時同時改動既有高頻列表映射。多查詢匯出使用隔離快照符合既有一致性要求，不能因此移除既有單一 SELECT 的最佳化或改全域隔離層級。

### 3. 直接填寫原始 PDF，保留全部靜態設計

使用後端 Apache PDFBox 載入原始 PDF 範本，複製其完整頁面與資源，再只填寫既有欄位。不重畫圖案、浮水印、框線、標籤、原文字型或版權文字，不新增頁首／頁尾圖稿，不點陣化整頁。主表保留 630 × 810 pt；A4 列印選「符合可列印範圍」。

實作時將相同位元內容的空白範本納入固定後端資源，記錄來源、檔案雜湊與欄位映射，不依賴本機 `D:` 路徑，也不接受任意使用者上傳範本。每個輸出頁以原版等價頁複製，按輸出頁次為欄位配置唯一名稱並維護 Widget 與正規欄位樹關聯，避免多頁同名值互相覆寫；只保留有冒險的頁數，原稿第二張空白頁不自動跟出。

填入文字使用可嵌入的繁中靜態字型及必要拉丁字型，保存字型來源與授權；原有印刷文字與其字型完全沿用。備註固定 11 pt，一般欄位以 11 pt 為起點；極小的靈魂幣使用方框沿用原稿 6 pt 與專屬範圍，不套用備註字級。以實際字寬量測，超量文字截尾加省略號，不因內容持續縮字或移入其他欄位；數值不得截成不同數字。缺字應明確回報，不產生看似成功的問號文件。

填寫時同步設定欄位的正規值 `/V` 與可直接顯示／列印的 `/AP` 外觀，並嵌入外觀實際使用的字型。不依賴 `/NeedAppearances` 或閱讀器用 Helvetica 重生中文外觀。保留原有 AcroForm；未明確要求平面化時不自動刪除表單。重新開檔核對正規欄位、各頁 Widget 的值與非空外觀；必要時保留原空白外觀的非文字圖形。不得將捨棄的備註留在完整 `/V`、隱藏文字或其他欄位。

主表固定為 `ceil(冒險數 / 3)` 頁，最後未用區塊留白，不建立附頁。頁碼只填入 Sheet #，不新增頁碼圖形。下載介面與 PDF metadata 說明角色摘要為匯出時資料、原稿包含舊季別文字、備註為截尾摘要且完整資料見網站／Excel；不為這些說明改版原 PDF。備註仍列獲得名稱與休整活動描述，必要短警告放最前方；完整冒險備註、未截尾活動、物品效果、獎勵敘述及資源來源拆分留在 Excel。

不採重建版面：使用者要求原版設計完全一致，原稿本身已有可用欄位。以原頁內容串流保留及欄位外渲染畫素比較驗證，比仿畫表格更直接且可檢查。

#### 備註容量量測與截尾

依原 PDF 兩頁六個冒險區塊的 Widget 矩形量測，三行寬度分別為 425.40 pt、539.16–539.64 pt、423.72–425.16 pt；第三行避開原本靈魂幣使用標籤，不能把它當成整行滿寬。各行左右各保留 4 pt，採最窄值驗算：

| 行 | 最小原寬 | 可用寬 | 11 pt 全形字數 |
| --- | ---: | ---: | ---: |
| 第一行 | 425.40 pt | 417.40 pt | 37 |
| 第二行 | 539.16 pt | 531.16 pt | 48 |
| 第三行 | 423.72 pt | 415.72 pt | 37 |

用本機 Noto Sans TC Regular（weight 400）實際量得一般中文字的 11 pt advance 為 11 pt，三行理論容量為 122 個全形字，因此採 **120 個可見字元**作固定上限（含標籤、標點、空白、警告與省略號）。A4 左右各 10 mm 留白時，630 pt 頁寬等比例縮成約 85.49%，備註實際字級約 9.40 pt；這是紙張幾何估算，尚非印表機實測。各行高度約 13.08–19.92 pt，實作需在原有行位校準 baseline 與垂直裁切，不以矩形寬度驗算代替垂直渲染檢查。

組成順序為必要短警告、冒險獲得、休整獲得、休整活動、故事獎勵；每組內沿用既有穩定順序。物品為「名稱×歷史數量」，獎勵只取名稱，活動取 `downtimeActivities[].description` 並加「休整：」標籤，例如「休整：抄寫法術，花費5天、50金」，未有內容的組省略。活動目前只有自由文字描述，故直接使用已存文字，不解析／推測活動名稱、天數或金額，也不再次扣除資源表已包含的變化。用「、」「；」等標點接成連續文字，不強制每組換一行；活動、名稱內的換行及連續空白正規化，避免在狹窄欄位浪費行數，不重複加入冒險自由備註或物品／獎勵效果描述。休整活動與其他內容共用既有三行／120 字上限，不額外保留三行或增加附頁。

截尾同時受 **120 字素上限及三行實際寬高**約束：超出時只保留能容納的前段與一個「…」，最多 119 字加省略號；不超出則不加省略號。寬字／fallback 字型可能需提早截尾。以 Unicode 字素為單位（可用 Java 標準正規表示式 `\X`）避免截斷組合字與 emoji；省略號也須量寬，末行放不下時移除前面的字素直到放得下。不以 UTF-16 長度或 PDF clipping 隱藏文字替代真正截尾，捨棄的文字不留在 PDF 的隱藏文字層。

此規則只作用於產生 PDF 的呈現文字，不修改共用快照 DTO、資料庫、草稿或 Excel；備註 120 字上限也不自動套到其他欄位。參考驗算已涵蓋六個區塊及中英數混合 120 字摘要，最終嵌入字型／字寬、截尾與紙本可讀性仍列實作驗收。

### 4. 紙本欄位對照

下表同時定義 PDF 與 Excel 的資料語意；「缺值」不是數字零。

| 範本欄位 | 來源與輸出規則 |
| --- | --- |
| Character Name | `characterName`；每張主表重複 |
| Player Name | 同一讀取快照的 `users.display_name` |
| Race, Classes and Levels | 種族及匯出時 `currentClassesString`，可含子職；職業沿用資料層英文標準字串，不另建翻譯詞表 |
| Faction | 角色選填派系，未填留空 |
| # of Soul Coins Carried | 同快照中倉庫 `CONSUMABLE && isSoulCoin` 的 quantity 加總；匯出時資料的說明放在下載介面與 PDF metadata，不改原標籤 |
| Sheet # | 在原有欄位填連續主表頁號，不另加頁碼或日期圖形；匯出時間存 metadata |
| Adventure Code / Name / Date / DM | 已存對應欄位，日期為遊玩日期，非建立日期 |
| Starting / Ending Level | 已存 `startingLevel`／`endingLevel`，缺值顯示「—」 |
| Level Accepted Y/N | 保留原標籤；已存 ending > starting 為 Y、等於為 N、缺值為「—」，如下降等異常另警告；不是玩家曾勾選接受升級的歷史證據 |
| Starting Gold / Downtime / Permanent Magic Items | 已存 `startingGold`／`startingDowntime`／`startingMagicItems` |
| Gold / Downtime / Magic Items +/- | 各資源已存的冒險變化加休整期變化；缺少任一必要數值時顯示未知，不猜測為零；拆分值完整保留於 Excel |
| Gold / Downtime / Permanent Magic Items Total | 直接取已存合計，不以匯出清單重新累計；魔法物品只表達永久物品歷史快照 |
| Adventure Notes / Downtime Activity | 必要短警告、自動獲得摘要與「休整：」活動描述；物品只列名稱×歷史數量、故事獎勵只列名稱；全部共用 11 pt／最多三行／120 字，超過直接截尾加省略號，不續頁或移到其他欄位 |
| Soul Coin Charges Used | `soulCoinChargesUsed` 在專屬欄位按實際空間截尾，不從現有持有量推算、不強制數值化，完整原文保留於 Excel |

### 5. 歷史與舊資料明確分開

有 `adventure_gained_item` 時只用其原始數量與內容；物品類型、來源、稀有度、分類、同調、靈魂幣、待補與備註均於 Excel 保存，PDF 只取固定容量內的名稱／數量摘要。零淨變化不代表沒有獲得／減少事件，不能在共用快照或 Excel 刪去明細或丟掉各來源減少數。

無快照的舊紀錄不宣稱獲得數為零。只將同角色且 `adventure_entry_id` 明確等於該筆的現存倉庫項目列為相容參考，歷史獲得數量留空，另列現存參考數量與資料來源標記；沒有可確定關聯時只顯示資料不足警告。不使用詳情元件的模糊字串 fallback，也不在匯出流程補建快照或移轉資料。這是匯出專屬的保守呈現，不改動既有詳情載入行為。

### 6. Excel 使用五張固定工作表

使用 Apache POI 產生 `.xlsx`，不自行拼 Open XML、不產生改副檔名的 CSV，也不新增前端套件。共用儲存格樣式，文字欄換行，合理限制欄寬，避免全表逐格自動量寬；資料列不合併，凍結首列與加篩選。儲存格一律明確寫入字串／數字／日期，不呼叫公式或建立超連結／外部關聯。

| 工作表 | 列與主要欄位 |
| --- | --- |
| 角色資料 | 一列角色摘要：角色名稱、玩家顯示名稱、種族、子職、派系、開卡職業／金幣／休整期、匯出時職業與金幣／天數／永久物品／靈魂幣摘要、匯出日期；說明「目前摘要不等於各筆歷史總計」 |
| 冒險紀錄 | 每筆一列：本次冒險編號、代碼、名稱、日期、DM、等級與職業起訖；三資源各起始／冒險變化／休整變化／合計；冒險與休整期物品減少數、備註、靈魂幣使用、紀錄提醒 |
| 獲得物品 | 每件一列：冒險編號、遊玩日期、冒險名稱、取得方式（冒險／休整期）、名稱、永久／消耗類型、稀有度、分類、同調、靈魂幣、獲得數量、庫存參考數量、備註；舊物品以備註說明當時數量未記錄、庫存僅供參考 |
| 休整活動 | 每項一列：冒險編號、遊玩日期、冒險名稱、完整描述 |
| 故事獎勵 | 每項一列：冒險編號、遊玩日期、冒險名稱、名稱、完整敘述 |

活頁簿不輸出角色、冒險、物品、活動或獎勵的內部 UUID，含隱藏欄位及續文亦不輸出。明細以本次冒險編號關聯，日期與名稱供人閱讀；同日同名冒險仍以不同編號區別。編號依本次完整匯出排序產生，不作為跨次匯出的永久識別碼。

Excel 面向一般玩家，不輸出列類型、資料編號、待補、歷史模型版本、建立／更新時間或技術性資料來源等系統欄位，不以隱藏欄位保留。取得方式、物品類型、稀有度、分類與是／否均使用網站既有中文用語，缺值留空。紀錄不連續等影響判讀的提醒仍以易懂文字保存，不因精簡而偽造完整歷史。

單格文字超過32,767個UTF-16單位時，僅為實際超長欄位新增「原欄名（接續 2）」「原欄名（接續 3）」等內容欄，放在同工作表右側、同一筆資料列中，不另建續文列或技術性關聯欄。沒有超長內容時不新增接續欄；按欄名順序串接即可還原全文，不切斷surrogate pair，排序也不會將同筆文字分散。冒險及子項目仍各自一筆一列。檔案驗證須重開比較全文，並驗證同名項目與不同欄位的接續互不覆寫。

兩個格式的共同欄位有相同語意，但資訊量不同：PDF 合併顯示資源淨變化及截尾獲得摘要，Excel 分欄保留已存來源數值及完整明細，不沿用 PDF 的 120 字限制。金額使用 `BigDecimal` 到輸出邊界；輸出 Excel 數字後以兩位小數精度驗證。遊玩日期及依匯出時區取得的匯出日期用 `LocalDate`，不經瀏覽器 UTC 轉換，不輸出紀錄建立／更新時間戳。

### 7. 沿用 M3 操作與既有請求失效機制

角色冒險列表的 header-actions 新增 outlined「匯出」按鈕搭配 `MatMenu`，項目直接是兩種格式。提示「匯出此角色全部已儲存紀錄，不受搜尋影響」，不加入未要求的格式設定／範圍 dialog。新增紀錄仍為主要 filled action；寬度不足時工具列換行，保留專案既有觸控範圍與文字縮放行為。

`AdventureService` 加直接 HTTP Blob 下載方法，繼續經 `authInterceptor` 沿用目前HttpOnly Cookie認證與`X-Session-Id`綁定，不把憑證放URL或新增Bearer token。回應在有效 session／角色 generation 且類型正確時才建立短期 object URL 並交給瀏覽器下載；使用後釋放，失效／銷毀時也釋放。JSON Blob 錯誤需讀取既有 message，不僅顯示 HTTP 字串。PDF 不自動開新視窗，避免非同步回應被 popup 阻擋。

共用`authInterceptor`對API的403／409 Blob錯誤先非同步讀取JSON代碼，沿用`AUTH_SESSION_CHANGED`的登入同步及`CSRF_INVALID`的CSRF更新；讀取完成後確認原登入仍有效，排入佇列的CSRF更新執行前也再確認，未登入的公開登入流程則僅在仍未登入時更新。原始`HttpErrorResponse`及Blob維持不變，保留匯出服務的訊息解析與失效檢查，不自動重送下載或寫入。無法讀取／解析的Blob照原錯誤傳遞，401不等待Blob解析，仍依現有登入身分檢查登出。

用 `LocalStore.sessionChanged`、同角色 `changes`／既有角色失效通知與 `takeUntilDestroyed` 取消進行中下載，並在真正交付前確認 owner、角色及 generation；非同步解析錯誤後亦檢查。處理 `finalize`，完成、失敗或取消均恢復 busy，舊請求的完成通知不能覆蓋新請求狀態。

狀態：尚未完整雲端載入／唯讀副本／已知離線時說明需要連線；零筆停用；載入中顯示 `role=status` 訊息並停用重複匯出；成功只表示已交付下載，失敗以既有訊息元件提供重試，401 仍交認證攔截器處理。資料明細不在 UI 重複組裝，也不寫入 IndexedDB、RequestCache 或 service-worker data cache。現有 ngsw 無 API dataGroups，維持該設定即可。

深淺色沿用 semantic surface／on-surface／outline／error tokens；按鈕與選單具明確名稱、可見焦點、標準鍵盤操作與非顏色狀態。無新動畫或自訂控制項。PDF 是文件排版，刻意不套網站卡片與彩色主題。

## Risks / Trade-offs

- [原版內容或多頁欄位被意外改動] → 固定範本雜湊、頁面內容保留檢查、欄位外畫素比較、多頁唯一欄位名稱及 `/V`／Widget／`/AP` 一致驗證；舊版規則字句保留原貌但不進計算。
- [紙本截尾省略部分獲得名稱] → 使用者已指定以紙本列印為優先，11 pt／三行／120 字與實際字寬共同限制，截尾加省略號且下載介面／metadata 說明，完整明細保留於網站／Excel，不增加附頁。
- [固定格位與中文／長文字衝突] → 實際字寬與行位測量、嵌入字型、範圍內換行及截尾；用 119／120／121 字、寬字、中英混合、emoji 與長獎勵渲染驗證不侵占下一筆。
- [舊紀錄無法還原原始收穫] → 顯示未知與相容來源，不用現有庫存假裝完整歷史。
- [大量紀錄造成記憶體或請求時間壓力] → 產生器在交易外、關閉文件／字型／串流資源，合成大資料測量時間與峰值記憶體；先不做佇列，但不得靜默限制匯出筆數。若超過現有服務容量，實作驗收前提出容量與處理方式調整。
- [跨帳號晚到回應或檔案留存] → 伺服器每次驗證 owner、回應 no-store，前端按既有 session／角色失效規則丟棄結果，不保存應用副本；已交付瀏覽器的下載檔由使用者自行管理。
- [新增依賴與字型資源] → 實作時選相容 Java 17 的受維護版本、記錄來源／授權並執行既有建置，不新增執行時網路字型下載。

## Migration Plan

不需資料 migration。實作順序為共用匯出快照與權限、兩種產生器與 API、前端入口、文件同步與驗收。後端先可接受新端點，再讓前端提供入口；發布依 VERSIONING.md 與既有 CI/CD，不在本次規劃操作正式環境。

回退只需移除／停用前端入口與回退應用版本，沒有已寫入的匯出資料需要清理。同步後的規格與 SRS 仍須如實反映實際可用版本。

## 實作量測與發布條件（2026-10-18）

1,000 筆冒險、每筆約900字備註及600字活動的合成資料，最終產生器在 Java 17／`-Xmx384m` 的本機隔離測試中：PDF 334頁、約8.64MB、4.01秒，10ms取樣的 Java heap 峰值364MiB；XLSX 約319KB、1.28秒、heap峰值142.4MiB。PDF欄位清單採一次設定，避免逐欄重新遍歷整個表單樹；字型連續文字一次繪製，欄位外觀串流壓縮。沒有截減筆數，也不加入背景佇列。

此量測不等於正式執行個體的容量保證。256MiB heap 的同規模PDF測試失敗，384MiB通過；發布前須納入應用程式本身、原生記憶體與同時匯出的餘裕，不能以512MiB總記憶體配置推定能承受多個千筆PDF。本次不變更部署容量或操作正式環境，未做正式環境及並行大量產檔壓測。這是已知容量邊界，未以靜默筆數上限迴避；若正式發布需要支援超出此範圍的負載，先另行確認容量或工作排程設計。
