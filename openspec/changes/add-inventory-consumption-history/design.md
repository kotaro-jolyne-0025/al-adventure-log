# Design

## Context

動機見 proposal.md。InventoryItemService 處理倉庫 CRUD；AdventureEntryService 的 createGainedItemInternal、updateGainedItemInternal、deleteGainedItemInternal 與 deleteEntry 也會新增、變更或級聯移除庫存。現有數量更正採差額套用且最低為零，不能為了新增紀錄改成重建整份庫存。

InventoryItemController 透過 MutationGuard 取得角色鎖與檢查微秒 updated_at。InventoryListComponent 已使用 Material tabs/dialog、LocalReadCache 及唯讀副本狀態；InventoryService 透過角色通知失效快取。一般 InventoryItemRequest 僅接受正數，來源更正為零目前會刪除庫存。資料庫的冒險／戰利品外鍵有 ON DELETE CASCADE，因此只記倉庫 API 會漏記。

現行 inventory-provenance 明文排除消耗快捷操作，本 change 明確修改該需求。state-consistency 的既有規則不變，在新能力中補充適用場景。匯出功能不在目前工作樹，不列為依賴或實作項目。

## Goals / Non-Goals

**Goals:** 復用目前庫存作為餘額來源，增加可追溯紀錄與原子消耗，讓所有現有數量寫入入口都留下原因；同一筆消耗同時支援庫存查帳與冒險回顧，不要求重複輸入。

**Non-Goals:** 不把系統改成事件溯源、不從歷史事件重建餘額、不合併同名物品、不改冒險表單與草稿契約、不提供所有動作的通用撤銷或完整欄位稽核。

## Decisions

### 1. 現有庫存加一張異動表

新增 inventory_movement。每列包含 id、character_id、原始 item_id（歷史識別，不對 inventory_item 設刪除級聯）、物品名稱／類型快照、operation、reason、quantity_before、quantity_delta、quantity_after、notes、created_at、updated_at。數量要求非負的前後值及 after = before + delta。新增紀錄的 updated_at 供關聯編輯與撤銷前置條件使用，不新增 revision 欄位。

- operation 區分 BASELINE、ACQUIRE、ADJUST、CONSUME、REMOVE、REVERSE；reason 區分手動操作、冒險獲得、來源更正及來源刪除。
- source_entry_id／source_gained_item_id 保存取得來源的歷史識別，不作會隨來源刪除的外鍵；usage_entry_id 才是可導覽的使用冒險，使用 SET NULL。usage_original_entry_id 與名稱／代碼快照保留已刪除關聯的歷史。
- character_id 跟隨角色 CASCADE 刪除；不允許孤立保留玩家資料。所有 HTTP 查詢與異動都先驗證該角色屬於目前玩家，沿用既有資料表權限／RLS 慣例，不能讓新表透過公開資料 API 外洩。
- reversal_of 指向被撤銷紀錄並具唯一限制；一筆消耗最多一筆反向紀錄。歷史數量與快照不可一般編輯，未撤銷消耗僅使用冒險關聯與備註可改。
- 建立 character_id + created_at + id 的分頁索引、item_id 查歷史索引與基準唯一限制。

選擇一張明確用途的表，避免全面事件溯源。既有 quantity 仍是目前餘額，歷史是操作證據，不能同時計算兩套目前庫存。

### 2. 服務層集中記錄，涵蓋所有庫存入口

新增小型 InventoryMovementService，提供記錄前後數量與原因的共用入口，不引入通用事件匯流排。InventoryItemService 與 AdventureEntryService 在原交易中呼叫，寫入失敗即整包回滾。

| 既有路徑 | 記錄行為 |
| --- | --- |
| 倉庫 create / update / delete | ACQUIRE / 實際差額 ADJUST / REMOVE |
| 冒險新戰利品、完整新增與編輯新增 | ACQUIRE，保留來源 |
| 更正戰利品與正差額重建 | ADJUST 或 ACQUIRE，reason 為來源更正；記實際套用差額 |
| 戰利品刪除、完整編輯移除子項目 | 移除前記 REMOVE，避免父層重複記錄 |
| deleteEntry | 查出所有即將級聯刪除的庫存，各記一次 REMOVE，再刪父冒險 |
| 角色／帳號刪除 | 直接一併刪除歷史，無須新增即將被刪除的事件 |

純名稱／備註更新不產生數量事件。物品建立後類型固定，倉庫與冒險明細更新、舊快照補建及來源同步均拒絕類型變更；拒絕不新增異動。既有歷史類型調整仍保存並影響舊消耗撤銷資格。明確刪除零數量物品可記 REMOVE 0，以區別用完與移除。

不採資料庫通用 trigger 推測原因：消耗與手動減量都是相同 quantity 更新，且使用冒險／備註來自業務操作。改用整合測試鎖定所有入口及級聯路徑，未來新增寫入入口必須使用同一記錄服務。

### 3. 消耗至零保留原物品身份

消耗端點允許將 quantity 設為 0，保留原 row／來源連結以便撤銷。持有列表及筆數只顯示 quantity > 0，總量計算自然不含零。一般手動新增／編輯仍接受正數，明確刪除仍刪 row。來源只更正名稱／備註且獲得數量不變時保留零庫存身份；來源數量更正或刪除若移除該 row，先前消耗不再可撤銷。

不使用同名搜尋重建物品，也不從異動快照復活已刪除來源。這可維持現有來源歸屬與不補貨原則。

### 4. 新增 API，保留既有 CRUD

以下路徑皆在 /api/characters/{characterId}/inventory 下，回傳 DTO，不暴露 persistence entity：

| 路徑 | 行為與前置條件 |
| --- | --- |
| POST /{itemId}/consume | quantity、notes、usageAdventureEntryId；以物品原始 updated_at 檢查 |
| GET /movements | 游標分頁，固定時間／ID 倒序；預設 50、上限 100；回傳 nextCursor |
| PATCH /movements/{movementId}/usage-adventure | 接受 usageAdventureEntryId 與 notes，至少明確提供一欄；省略保留、明確 null 清空；使用紀錄 updated_at |
| POST /movements/{movementId}/reverse | 使用紀錄 updated_at；鎖內檢查撤銷資格與最新物品狀態 |

consume 透過 guard.mutate(ITEM)；新增 MOVEMENT guard target，使關聯編輯與撤銷取得同一角色鎖並比對紀錄 updated_at。撤銷再讀最新物品、檢查該消耗後沒有其他數量／類型事件，更新物品與角色／相關來源冒險時間戳，新增反向紀錄；不呼叫會重複新增 ACQUIRE 的普通新增流程。所有物品、來源及使用冒險 ID 都驗證同角色，使用冒險查核在鎖內完成。

沿用 X-Expected-Updated-At；缺漏 428、格式不合法 400、過期 409。成功消耗後原時間戳失效，回應遺失時重送舊請求不會再扣。前端不自動取新時間戳重送。新增數量／備註驗證與整數溢位保護，備註上限 2000 字。

歷史關聯編輯不改事件 created_at，不改數量；來源刪除造成關聯清除時須推進紀錄 updated_at。游標依 created_at、id 穩定排序，讀取不以 OFFSET 位移。

GET /movements 接受選填 `usageAdventureEntryId` 與 `reversed=false|true`，兩者須成對提供。均未提供時回傳預設產品庫存紀錄；提供時先驗證冒險屬於路徑角色及目前玩家，僅查 `CONSUME` 且目前使用冒險 ID 相符、撤銷狀態相符的紀錄。狀態篩選僅供此冒險查詢，既有 true 參數保留相容性；產品畫面僅使用 false。空字串、非法 ID／布林值及不完整篩選拒絕，不能退回查全部資料。

篩選必須在後端分頁之前執行，不能下載角色第一頁再由前端找冒險，也不掃描全部角色歷史。2026-11-10 確認撤銷只在底層留資料：無冒險篩選的預設查詢排除 BASELINE、REVERSE 及有反向紀錄的原消耗，再套用游標與頁面上限；冒險畫面僅查 reversed=false。保留既有 reversed=true API 契約相容性，但產品畫面不提供其入口或載入。沿用既有 movement DTO、所有權驗證與撤銷資格；不新增消耗副本表或修改冒險完整儲存／草稿的子清單契約。未取得全量時不顯示全場總數或合計，首版不增加統計 API。

### 5. 安全撤銷的首版預設

本提案採「該物品沒有後續數量／類型異動才可撤銷」的保守預設，避免消耗後已盤點數量或修正來源，再補回造成重複庫存。可撤銷用到零；名稱／備註與使用冒險編輯不影響資格。資格檢查與更新在同角色鎖內完成，reversal_of 唯一限制作最後防線。

這不是任意歷史回溯：早期消耗若已有後續異動不能直接撤銷，需要使用現有手動調整留下更正。相比無條件補回或重新運算所有後續事件，這個限制較容易理解與驗證；在實作前提案審閱時明示此取捨。

### 6. 介面與狀態

庫存紀錄與冒險「本次使用」不提供常駐重新整理按鈕；沿用開啟時載入、操作成功及頁面恢復可見時重新讀取。讀取失敗仍提供重試，有下一頁仍提供載入更多。

啟用基準僅於後端保留，畫面不呈現基準列或說明；沒有後續操作時沿用空狀態。紀錄列採物品列表的卡片間距與左側名稱／來源、中間數量、右側時間與操作的排列；窄螢幕換行且操作靠右。紀錄列的編輯與撤銷沿用消耗品列的 Material 圖示按鈕：16px 鉛筆及回復箭頭，搭配既有「編輯紀錄」與「撤銷這次使用」tooltip，無障礙名稱包含物品名稱。倉庫與冒險共用此呈現；保留鍵盤焦點、既有停用條件及撤銷確認，不以刪除圖示代替撤銷。

2026-11-10 已確認的 `output/prototypes/inventory-navigation-demo.html` 取代三個同層頁籤的導覽。倉庫區分物品清單與庫存紀錄兩個檢視；物品清單以單選切換群組選擇「永久物品／消耗品」，庫存紀錄使用標題旁獨立的圖示加文字入口。角色層級「冒險紀錄表／倉庫」導覽保持不變。不新增每筆物品的歷程按鈕／視窗，也不設待補登數量或入口；未選冒險的消耗不是必須完成的待辦。

#### 6.1 桌機與手機布局

- 寬版：標題列左側為倉庫，右側為庫存紀錄與新增物品；下方為雙分類切換、搜尋、稀有度與排序。沿用既有物品列的內容、右側操作與排序功能，不以原型的少量選項縮減正式功能。
- 窄版（內容區寬度不大於 600px）：雙分類各占半寬，標籤使用「永久物品／消耗品」，筆數為各類 quantity > 0 的物品筆數，不是數量加總，也不受搜尋／稀有度篩選影響。文字不得縮小、截斷或靠水平滑動才能看完整；筆數增長時允許群組高度增加及內部換行。
- 手機標題列保持「庫存紀錄」文字與圖示可見；新增物品可縮為加號，保留「新增物品」無障礙名稱。空間不足時工具列換行，不以隱藏紀錄入口或壓縮字體騰出空間。
- 手機搜尋旁顯示篩選按鈕，可展開／收合完整稀有度選項；收合不清除選值，有啟用篩選時以非僅顏色的選取狀態或標記辨識。排序使用精簡入口，仍保留既有稀有度／取得時間及升降冪，沿用目前儲存的排序偏好。
- 依可用寬度調整布局；320、390、600px 與桌機寬度，以及斷點前後均須無水平溢出。字體放大時允許換行，不能因換裝置模式重置目前分類或操作中的輸入。

#### 6.2 庫存紀錄導覽與返回

開啟庫存紀錄後，顯示「庫存紀錄」標題與「返回倉庫」入口，隱藏物品分類、物品搜尋／稀有度／排序及新增物品。庫存紀錄仍查該角色全部可見異動，不套用物品清單分類或篩選；紀錄內容、分頁、備註、右側編輯／撤銷及冒險的本次使用維持既有規則。首次進入按需載入，沒有常駐重新整理按鈕。

同角色內返回倉庫時保留分類、搜尋字串、稀有度選值、排序欄位／方向與捲動位置；物品有異動時先顯示有效的新資料，再恢復合理位置，不為了保留舊位置重播失效快取。原物品消失時回到鄰近清單位置或分類標題。頁面內返回與從本清單開啟紀錄後的瀏覽器上一頁行為一致，不能把玩家送出角色頁面；不要求新增跨登入的搜尋／捲動持久化。角色或帳號切換時清除前一上下文的暫存清單狀態，既有排序偏好的儲存方式不變。

分類與紀錄檢視分開表示，不能再依 activeTab 的第三個索引推定新增物品類型。新增時採用目前分類；物品編輯仍不允許修改類型，永久物品仍各自獨立且數量為 1。資料更新、衝突保留輸入、所有權及唯讀規則不變。

導覽／分類使用適當的連結或單選群組語意與可見選取狀態；以鍵盤可操作，所有圖示按鈕有名稱。進入紀錄後將焦點移至紀錄標題，返回移回原入口；因條件變化入口已不存在時回到物品標題。手機篩選須有展開狀態與控制目標，收合後不得留下不可見的可聚焦元素。

#### 6.3 原型與實作界線

HTML 僅確認導覽、工具列與響應式排列；預覽尺寸按鈕、示範帳號、固定角色資源、示範提示及記憶體資料不進產品。原型中的簡化新增／編輯、部分稀有度、固定日期、有限歷程及未完整模擬的撤銷資格不作正式契約；沿用現有表單、全部欄位、系統登記時間、後端資格判定、快取失效與分頁查詢。不修改角色看板或冒險表單，不新增 API、migration 或離線寫入。導覽新增文案限已確認原型的「永久物品」「消耗品」「庫存紀錄」「返回倉庫」，原型的示範成功提示不視為正式文案授權。

消耗視窗由消耗品列開啟：數量預設 1、顯示目前數量、備註與冒險選填。冒險選單使用既有角色冒險查詢，讀取失敗可不選冒險繼續消耗；不允許保留已無法驗證的選項。送出中防重按，取消不寫入，失敗保留輸入；409 要重新查看雲端狀態，不能靜默重試。

歷史檢視按需載入，先使用記憶體 RequestCache，不新增離線歷史儲存；角色快取失效時同時清除所有歷史頁。離線顯示無法更新／重試狀態，不將讀取失敗當成空歷史。沿用 LocalReadCache 的 freshCharacters 與 readOnly，所有新寫入在副本狀態下停用。冒險造成的庫存異動也須失效歷史；先失效再通知 HUD，沿用現有帳號切換保護。

2026-11-09 確認的資訊分工取代先前僅依 C 版排版的方向：

| 資訊 | 庫存紀錄：查明數量如何變動 | 冒險詳情「本次使用」：回顧該場使用 |
| --- | --- | --- |
| 範圍 | ACQUIRE、ADJUST、有效 CONSUME、REMOVE，包含永久物品 | 該場目前關聯的有效 CONSUME |
| 首層資訊 | 物品名稱、取得來源、動作、數量增減、當時剩餘、完整本地登記日期時間 | 物品名稱、取得來源、此次用量 |
| 使用冒險 | 有效消耗顯示；未選擇與已刪除要區分 | 由頁面上下文提供，不重複列出 |
| 備註 | 直接顯示，保留換行；空白不占位，不提供詳情／整列展開 | 直接顯示，保留換行；空白不占位，不提供詳情／整列展開 |
| 操作 | 有效消耗的「編輯紀錄」及撤銷直接放在紀錄列 | 有效消耗的「編輯紀錄」及撤銷直接放在紀錄列 |
| 已撤銷 | 隱藏原消耗及反向補回列；底層保留完整資料 | 隱藏原消耗，不提供已撤銷區塊 |
| 起始庫存 | 不顯示，基準僅保留於後端 | 不顯示 |

庫存與冒險清單皆按登記時間／ID 倒序。庫存紀錄依本地登記日期顯示分隔線，跨頁同日接續原日期群組。冒險本次使用維持逐筆清單。登記時間不當成實際使用日期，也不新增實際使用日期輸入。來源與使用冒險採不同欄位，不由來源推定用途。同名但不同穩定物品 ID 的紀錄分開；同一物品的多次消耗也逐筆呈現，首版不新增彙總。數量使用「個」，當時剩餘不得叫作目前庫存，冒險列首層不顯示目前庫存或歷史餘額。

兩個檢視復用現有使用冒險視窗與安全撤銷流程，操作對象都是同一 movement ID 與原始 updated_at；禁止複製登記、再次扣減或一般編輯歷史用量。取得、調整、移除、基準與反向紀錄沒有消耗關聯編輯或通用撤銷。可讀性沿用語意色、文字狀態、可見焦點、讀屏回饋與 dialog 焦點管理；更新後原列消失時，焦點移到該區塊標題或其他合理可操作位置。

### 7. 兩個檢視的一致性與載入

2026-11-10 後續確認：取消備註折疊，直接呈現原有 movement.notes。共用編輯視窗同時編輯使用冒險與備註，預填原值，可清空，維持 2000 字限制；既有 PATCH /movements/{id}/usage-adventure 接受 notes 與 usageAdventureEntryId，至少明確提供一欄。省略欄位保留原值；使用冒險明確 null 才清除，notes 明確 null／空字串才清空。編輯視窗未更動冒險時省略該欄，避免只改備註意外清掉已刪冒險的歷史快照。沿用 MOVEMENT 時間戳、角色鎖、唯讀、衝突保留輸入及角色級快取失效，不更改數量、原登記時間或產生新異動，不新增 migration。冒險選單讀取失敗時沿用禁止送出，避免誤清關聯。視窗標題「編輯紀錄：物品名稱」、操作「編輯紀錄」、成功提示「已更新消耗紀錄。」已獲使用者確認。

畫面亦排除回應中的 REVERSE 與 reversed=true 原消耗，避免前端更新而本機舊後端尚未重啟時重新顯示撤銷紀錄。前端保留伺服器游標，不以過濾後筆數推斷已讀完；尚有下一頁時不顯示空清單結論。正式分頁完整性仍由新版後端分頁前過濾保證。

AdventureDetailComponent 的「本次使用」獨立讀取上述篩選頁，不取代或混入原有「獲得物品」。空白、載入、錯誤及重試分開呈現，歷史查詢失敗不影響已成功載入的冒險內容，也不顯示假空清單。來源冒險刪除、物品歸零或移除時，仍使用歷史快照顯示已登記的消耗。若目前冒險本身已刪除或失去存取權，清除它的使用區塊；庫存紀錄保留已刪關聯標示。

InventoryService 的 RequestCache key 包含角色、使用冒險篩選、撤銷狀態與游標，不能只用 cursor。成功消耗、關聯編輯或撤銷後，沿用角色級失效通知清除無篩選及所有冒險篩選頁，重設已載入游標並重新讀取受影響檢視。從 A 改為 B 同時失效 A、B；清除關聯只從冒險區塊移除，仍保留在庫存紀錄。修改關聯不更改 created_at，不產生新消耗，也不改冒險獲得快照或目前庫存。

晚到回應不得覆寫切換冒險、角色、帳號或失效後的新結果；重新取得最新角色狀態前不開放寫入。冒險讀取為本機副本時，即使某次歷史回應成功也不能解除唯讀限制。兩個檢視共同遵循 state-consistency；不新增離線歷史儲存，亦不自動重送過期時間戳。

玩家可見提示文案沿用先前已確認的消耗／關聯提示及「尚無異動紀錄。」空狀態。2026-11-10 使用者確認撤銷提示更新為「撤銷後會補回本次消耗數量，並從畫面移除這次登記。是否繼續？」，成功提示沿用「已撤銷消耗。」。

原型 `output/prototypes/inventory-consumption-adventure-flow.html` 是資訊層級與操作流程的參考；範例、重設按鈕、原型說明與未分頁的筆數不是正式產品需求。本次新增檢視的完成證據獨立記在 tasks.md 第 7 節。

## Risks / Trade-offs

依 2026-11-12 使用者最新決策，桌機與手機排序統一放在搜尋／篩選下方，只保留一個共用範本入口。桌機依內容寬度靠左，手機填滿可用寬度；新增物品留在標題列，庫存紀錄檢視不顯示排序。

- [服務入口漏記] → 明列 AdventureEntryService 與 CRUD 的全路徑整合測試，級聯刪除前逐筆記錄，驗證每個實際異動恰好一次。
- [舊後端版本不會寫異動歷史] → 新表結構可相容，但功能啟用後不能宣稱直接回退舊程式仍保有完整歷史；優先向前修復。
- [零數量 row 改變列表筆數] → UI 持有列表及計數排除零，冒險更正、靈魂幣與永久總量回歸驗證。
- [安全撤銷限制較保守] → 顯示不可撤銷原因並保留手動調整；不悄悄重算歷史。
- [歷史量增加] → 按角色游標分頁與索引；不做全量載入或新的持久快取。
- [舊資料無完整來源／異常數量] → 不猜測；在隔離升級驗證列出阻擋條件，不靜默修正玩家數量。

## Migration Plan

1. 實作時使用下一個未使用的 Flyway 編號，不修改已套用 migration。新增表、限制、索引及既有權限慣例；以每物品唯一 BASELINE 回填現有數量，標示為啟用基準。
2. 基準建立與新寫入路徑切換必須避免舊後端在回填後繼續漏記。以首次新後端功能啟用前的受控寫入切換完成基準校準；若需部署維護窗口，另在發布評估取得授權。本次不部署、不操作正式 DB。
3. 在隔離資料庫驗證全新建庫、從已發布版本升級、初始化重跑、物品刪除後重跑不復活、基準守恆、角色刪除及來源級聯。異常 null／負數庫存先報告，不以零取代。
4. 前後端與 migration 一起驗收後才對使用者開放；依 VERSIONING.md 另行進行發布評估。新功能啟用後若故障，保留歷史表與基準，優先修復新寫入流程，不刪紀錄或回填假的完整歷史。
5. 完成實作與驗證後同步 SRS、database-schema.md、user-stories.md 及主規格。2026-11-09 的雙檢視擴充沿用既有 schema，不新增或改寫 migration。

## 方案 A：冒險詳情的消耗紀錄卡片

沿用詳情頁的卡片樣式及既有位置：在「獲得消耗品」區塊之後、後續詳情區塊之前。桌機與手機皆在詳情頁直接顯示卡片，不增加頁籤、入口或路由；即使「獲得消耗品」因無資料而未顯示，卡片仍留在原區段。標題由「本次使用」改為「消耗紀錄」，標題下方顯示「請至倉庫登記消耗，並選擇這場冒險。」標題與說明在空白、載入與讀取失敗時仍可辨識，清單沿用各自的狀態及提示。
