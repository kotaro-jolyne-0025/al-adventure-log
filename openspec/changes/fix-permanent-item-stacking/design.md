# Design: 永久物品數量與類型限制

## Context

目前永久物品和消耗品共用數量輸入，且倉庫與冒險編輯 API 接受類型變更。永久物品應逐件管理，而既有資料可能已有數量大於一的紀錄，因此不能以自動修正資料的方式處理。

## Decisions

- 後端在信任邊界拒絕新建多件永久物品、永久物品數量異動，以及類型變更。
- 更新既有永久物品時，未提供數量就保留原值，讓歷史上數量大於一的資料可編輯其他欄位。
- 前端新增時仍可選類型；編輯時唯讀顯示類型，永久物品不顯示數量欄位。
- 冒險紀錄快照、關聯倉庫物品與舊資料補建路徑共用類型不變規則。

## Risks

- 舊資料中數量大於一的永久物品仍會保留；需由玩家自行逐件整理。此修正不會刪除或拆分既有資料。
- 舊版客戶端仍會被後端拒絕不合法的類型或數量修改。

## Migration Plan

不需要資料庫 migration。部署後由後端 API 即時執行驗證。
