# Design

## Context

動機見 `proposal.md`。`app.html` 已有登入使用者選單與未登入更多選單，首頁有獨立頁尾。`AppFooterComponent` 目前未由根元件引用，且包含舊版號，不適合為這次入口直接啟用。現有 Angular Material Dialog、Menu、Button 與 Snackbar 可沿用。

既有法律聲明宣告核心功能免費且無訂閱牆；這次外部贊助不得提供付費功能或權益。使用者已提供 Portaly 網址 `https://portaly.cc/kiranfreedom` 作為贊助入口；網站使用此原始網址，不推定或拼接付款子路徑。

## Goals / Non-Goals

**Goals:** 以共用設定保持三處入口一致；不離開正在編輯的頁面即可取得聯絡資訊；聯絡與贊助入口一併提供。

**Non-Goals:** 站內客服表單、自動寄信、工單、付款 SDK、付款狀態回寫、會員權益及後台設定介面。

## Decisions

### 1. 全站選單加首頁頁尾

- 登入選單在法律聲明後、版本區前加入聯絡／贊助；未登入選單在版本區前加入同一組入口。
- 首頁頁尾在法律連結旁加入入口。
- 選單項目保持相同順序，透過共用 template 避免登入／未登入邏輯分歧。
- 聯絡／贊助前方分別使用專案既有 Lucide Mail／Heart 線條圖示，選單 20px、首頁頁尾 18px，沿用全域圖示對齊與間距。圖示繼承文字色並標示 aria-hidden，保留文字名稱。
- 不在工具列直接新增常駐按鈕，讓窄視窗維持現有布局；不新增頁面路由或啟用未使用的全站 footer，避免擴大這次範圍。

### 2. 聯絡彈窗與原生郵件連結

新增 standalone 聯絡彈窗，由根元件與首頁共用。內容如下：

| 區域 | 文案／控制 |
|---|---|
| 標題 | 聯絡我 |
| 說明 | 遇到使用問題或想提供建議，歡迎寄信給我。 |
| 信箱 | adventurelog-contact.cupping865@simplelogin.com，可選取文字 |
| 補充 | 請描述操作步驟、遇到的問題及使用裝置；需要時可附截圖。 |
| 主要操作 | 寄信給我，原生 anchor 搭配 Material outlined button |
| 次要操作 | 複製信箱，Material text button |
| 關閉 | 關閉，Material text button；支援 Escape |

以 URI 編碼預填主旨，僅包含固定主旨與信箱。複製使用瀏覽器剪貼簿；捕捉拒絕與不可用狀態，用既有 Snackbar 回報結果，保留手動選取。沒有郵件處理程式時無法可靠判斷是否成功開啟，因此信箱與複製始終可用，不宣稱寄信成功。

直接 `mailto:` 雖較短，但缺少清楚展示信箱及可回復的複製操作；獨立聯絡頁則會導覽離開表單，故使用彈窗。

### 3. 靜態公開設定

新增小型 `core/config/site-links.ts` 作為單一來源，包含 `contactEmail` 及選用 `sponsorshipUrl`；聯絡信箱使用已確認的 `adventurelog-contact.cupping865@simplelogin.com`，贊助網址使用 `https://portaly.cc/kiranfreedom`。以 URL parser 檢查 HTTPS、主機及無 username/password，僅有效時產生可用贊助連結。不新增 API 或執行期設定服務。

本站只設定公開聯絡別名；真實收件信箱僅在外部轉寄服務設定，不寫入前端、公開文件或測試資料。首頁、根元件與彈窗共用設定，不在每個 template 各自硬寫網址。

### 4. 贊助使用原生外部連結

有效設定時使用 `<a mat-menu-item>`／首頁原生 anchor，搭配 `target="_blank" rel="noopener noreferrer"`。連結可見文字保留「贊助支持」，附外部連結圖示與讀屏說明「外部網站，新分頁開啟」，不只靠 tooltip 表達。登入／未登入選單僅呈現贊助連結，不附加贊助說明段落。

初始設定使用已提供的 Portaly 網址；若日後清空設定則隱藏贊助入口。使用 anchor 可讓使用者保留瀏覽器的連結操作，不需要自行 window.open 或增加確認彈窗。

### 5. 主題、布局與可及性

沿用既有語意色彩與 Material 互動狀態，本文用 onSurface，補充文字用 onSurfaceVariant，連結用 primary；焦點清楚可見，hover／pressed 沿用元件狀態層。主要操作有文字標籤，圖示作裝飾。

彈窗沿用現有 dialog 視窗寬度策略，窄視窗限制至可用寬度，信箱可斷行、操作列可換行。依本專案既有 Web 控制項規範，點擊區域至少 44px 高，避免固定文字容器高度；檢查 200% 文字放大及深淺色實際對比。入口用 button 開啟彈窗，寄信／贊助用 anchor，複製用 button。

從選單啟動彈窗時，選單關閉與 dialog 還原焦點可能競合；關閉後焦點回到可見的選單觸發按鈕。首頁則回到「聯絡我」。不新增動畫，沿用現有降低動態效果設定。

## Risks / Trade-offs

- 郵件處理程式與剪貼簿權限受裝置限制 → 信箱永遠可讀、可手動選取，複製失敗有明確提示。
- 外部頁面可能變更 → 實作驗收時確認使用者提供的 Portaly 頁面可開啟並能找到贊助操作；不推定付款已完成或頁面內容已核驗。
- 現有聲明包含免費與非商業措辭 → 啟用前檢查贊助頁文案與本站說明是否一致；若出現付費權益或需要調整既有聲明，另行處理需求，不自行將本提案視為合規判斷。
- 公開別名可能收到垃圾郵件 → 使用可停用或更換的別名；啟用前測試收信與回信，確認寄件地址及簽名不暴露私人地址。

## Migration Plan

無資料遷移。實作後執行前端 production build 與相關行為驗證，再同步 SRS 和主規格。發布依 VERSIONING.md 及既有 CI/CD，這次規劃不授權提交或發布。停用贊助可將網址清空；整體回復為還原這次前端變更。

## External Verification

已取得使用者指定的 Portaly 網址；實作階段已用瀏覽器確認個人頁可開啟、有「贊助連結」且 support 頁呈現支持表單。本站仍使用指定的原始網址，未操作付款。驗證細節見 tasks.md。
