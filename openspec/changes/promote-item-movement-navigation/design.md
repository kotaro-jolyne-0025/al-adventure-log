# Design

## Context

character-shell 現有兩個角色導覽目的地，600 CSS px 以下使用底部導覽，以上使用上方頁籤。inventory-list 以 `inventory?view=history` 顯示共用 inventory-history，並有倉庫入口、返回與焦點管理。InventoryMovementMapper 的角色查詢已包含兩類物品；冒險查詢限定有效 CONSUME。InventoryMovementService 不為相同數量與類型的 ADJUST 建立事件。

## Goals / Non-Goals

目標是提升既有歷史的導覽層級與釐清範圍，不重建歷史服務。不新增篩選器、永久物品數量編輯、逐物品歷程、消耗輸入入口或 metadata 修改稽核。

## Decisions

- 採使用者選定的手機底部第三格、桌機上方第三頁籤。桌機側欄會減少內容寬度，倉庫內入口則保留額外切換步驟，皆不採用。三個目的地都只屬於目前角色，不擴大全站導覽。
- 重用 `inventory?view=history` 與既有清單，無需新增平行路由或資料模型。shell 的選取判斷須先辨識 history query，再辨識 inventory；詳情仍屬冒險，表單沿用隱藏導覽規則。保留深連結、重新整理、瀏覽器上一頁／下一頁。
- 移除倉庫重複紀錄入口與歷史返回工具列，改由同層導覽切換；移除控制後同步修正焦點目標。列表與歷史同元件切換時，不清掉倉庫搜尋、分類、篩選、排序及可恢復捲動；狀態按角色隔離。資料失效仍須重新讀取，不為保留畫面而重播過期資料。
- 全角色檢視名稱統一為「物品異動紀錄」，沿用既有歷史圖示、收合列、日期分隔、正負數及選單。永久物品取得顯示「取得」，真實庫存差額顯示「調整」，刪除顯示「移除」。只改名稱／來源文字／備註不建立數量歷史，永久物品不可消耗或撤銷消耗。此處並未新增永久物品調整數量的操作。
- 冒險詳情繼續叫「消耗紀錄」，因為其資料僅為該場使用的消耗品，不把獲得事件重複加入。兩個檢視繼續操作同一 movement。
- 不縮小六字導覽標籤掩蓋空間不足；窄視窗可換行、增加導覽高度，內容底部補償與 safe-area 同步。保留既有語意 token、焦點、目標尺寸與選取指示。全站頂欄、角色卡與「資源總覽」不改設計。

## Risks / Trade-offs

- query 同屬 inventory 易雙重選取 → 單一目的地判斷與深連結測試。
- 六字標籤增加底欄高度 → 320／360／390／600／601 px、文字放大及安全區驗證，不遮住最後一筆與載入更多。
- 永久物品可能已有歷史 → 顯示已存在有效事件，不清空、不補造過去紀錄，BASELINE 與撤銷雙方仍隱藏。
- 導覽共用 CSS 可能影響排序 → 同資料、同視窗比較冒險及倉庫排序膠囊寬度與右側留白，保留桌機內容寬度，不增側欄。

## Migration Plan

只變更前端導覽與呈現，重用既有 API，不新增 migration 或改正式資料。實作時同步 DESIGN.md、SRS、主規格及舊 change 中現行導覽描述，註明此 change 接續取代的入口規則；不宣稱尚未實作內容已完成。回退本次前端變更可恢復原入口，不影響既有事件。
