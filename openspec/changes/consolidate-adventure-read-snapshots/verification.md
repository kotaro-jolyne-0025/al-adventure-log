# Verification

2026-10-16，完成本機實作及驗收，並已透過 [PR #36](https://github.com/kotaro-jolyne-0025/al-adventure-log/pull/36) 合併及部署。以下數值為部署前比較；部署後的正式效能重測依使用者指示延後。正式站驗證只讀取既有角色／紀錄／倉庫與請求日誌，未修改玩家資料。

## 量測方法與界線

- 正式入口為 `https://aladvlog.com`，Google 登入；已發布畫面版本 v2.1.0，確切 revision 私下留存。
- 同一台電腦、同一 Edge 設定檔操作。本機使用獨立暫存 PostgreSQL 與合成帳號，與正式 Google 帳號分屬不同資料庫；登入之後的資料導覽才列入比較。
- 最終本機與正式皆為 3 個角色、選定角色 10 筆冒險及 31 筆倉庫物品；角色列表約 150 KB／151 KB。本機資料、頭像皆為合成，沒有複製玩家資料；紀錄內容／子項目不完全相同。
- 計時從自動操作點擊到最新資料的編輯控制可操作，避免把副本先出現當作完成。數值包含瀏覽器工具橋接、點擊及輪詢成本，**不是純瀏覽器 Performance API，也不是承諾使用者一定會等待此秒數**。
- 角色入口與返回角色列表各 10 次，其餘各 5 次，以下使用中位數。單次首次進入約 2.29–2.52 秒，但未清除兩邊既有瀏覽器／程式碼快取，故不當作嚴格冷載入 A/B 或伺服器冷啟動結果。

## 伺服器證據與修正

正式 Cloud Run 成功請求日誌的測量期間描述性中位數，與本機 HTTP 五次樣本分開記錄：

| API | 正式 request latency | 本機 HTTP | 本次處理 |
| --- | ---: | ---: | --- |
| 角色列表 | 407.1 ms | 6.9 ms | 保留既有單查詢 |
| 角色 HUD | 327.7 ms | 5.8 ms | 保留既有單查詢 |
| 冒險列表 | 866.9 ms | 8.4 ms | 四次 SELECT 加交易設定 → 一次 SELECT |
| 冒險詳情 | 799.4 ms | 5.3 ms | 主紀錄／活動／獎勵／相鄰快照／物品／必要舊庫存 → 一次 SELECT |
| 新增預設值 | 675.0 ms | 4.7 ms | 角色與永久物品數量加總 → 一次 SELECT |
| 倉庫 | 379.9 ms | 5.7 ms | 保留原讀取流程 |

日誌統計包含測量期間首次請求，與 UI 樣本不是逐筆 A/B。根據既有跨區架構及程式碼，多次 DB 往返是可消除的成本；本次合併三條讀取路徑，沒有把本機毫秒數當作正式改善結果。省下的正式時間須在部署後量測，不作推估保證。

## 規格與資料一致性

- 三個讀取各只有一個 owner-filtered SELECT。PostgreSQL statement snapshot 保證主紀錄、所有子集合、原始時間戳、預設資源及下一筆快照來自同一視圖；只有這三個已整併讀取移除額外 REPEATABLE READ 包裝。
- 所有 MutationGuard、寫入交易、角色短暫鎖、帳本差額、物品數量與歷史不補貨邏輯保持。Controller 繼續只回傳 DTO，內部讀取實體不外露。
- 既有快取新鮮度、帳號隔離、寫入失效、離線唯讀及草稿策略保持。
- 新增實際 PostgreSQL 測試涵蓋空列表／無權限差別、獨立多子集合、物品 enum／布林／來源、舊庫存、下一筆不連續警告、微秒精度，以及另一連線提交時不混合主子資料。
- 本機雙視窗實測：A 儲存成功；B 儲存被拒絕且保留輸入與查看新版入口。重新載入 B 後仍能查看包含原輸入的草稿，舊版草稿不自動套上新版時間戳重送。API 再讀確認 A 的內容與金幣累計保持。
- 本機倉庫新增／修改／刪除成功；舊時間戳更新回傳 409；歷史獲得明細沒有被倉庫異動改寫。
