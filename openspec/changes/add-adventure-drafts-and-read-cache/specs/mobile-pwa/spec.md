## MODIFIED Requirements

### Requirement: Safe area and input ergonomics
手機版 SHALL 避開頂部瀏海與底部手勢區；角色、冒險及物品表單的儲存／取消區 SHALL 位於表單末端並隨內容捲動，MUST NOT 固定或黏附在視窗底部。操作區 SHALL 不遮擋必要欄位，並保留底部安全區。寬度不超過 768 CSS 像素時輸入文字 SHALL 至少 16 CSS 像素，關鍵按鈕點擊高度 SHALL 至少 42 CSS 像素。

#### Scenario: 有底部手勢區的裝置
- **WHEN** 玩家在有底部手勢區的手機填寫並捲動至表單末端
- **THEN** 儲存按鈕位於安全可點擊區域，最後一個輸入欄位可完整捲入可視範圍

#### Scenario: 捲動閱讀三種表單
- **WHEN** 玩家向上捲動閱讀角色、冒險或物品表單的中間欄位
- **THEN** 儲存／取消區隨表單末端離開畫面，不持續占用視窗底部

### Requirement: Reachable mobile adventure form actions
手機冒險表單 SHALL 將儲存／取消列置於表單末端的正常文件流並避開安全區，各種可視高度 SHALL 採相同行為。最後欄位、草稿狀態、錯誤提示及操作列 SHALL 可依序捲入視窗，不重疊遮擋。操作列 SHALL 保留既有儲存禁用條件，錯誤定位 SHALL 保留展開及移動焦點功能。

#### Scenario: 長表單與短視窗
- **WHEN** 玩家在寬度不超過 768 CSS 像素的手機捲動冒險表單，或視窗高度縮小到不超過 600 CSS 像素
- **THEN** 操作列皆在表單末端隨內容捲動，最後欄位、儲存與取消沒有互相遮擋

#### Scenario: 錯誤提示
- **WHEN** 玩家在手機提交冒險時驗證失敗
- **THEN** 錯誤在末端操作附近完整換行可讀，定位入口仍可展開並前往錯誤欄位，提示不跟隨視窗固定

#### Scenario: 草稿與錯誤提示
- **WHEN** 玩家在手機填寫冒險或提交時驗證失敗
- **THEN** 草稿狀態及錯誤在末端操作附近完整換行可讀，定位入口仍可展開並前往錯誤欄位，提示不跟隨視窗固定
