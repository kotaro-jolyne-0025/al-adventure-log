# Proposal

## Why

玩家跑團時用手機查看及記錄，回家再用電腦整理；正式資料需要雲端同步，但手機誤關、切換 App 或暫時訊號不佳不應讓未儲存輸入輕易遺失。加入冒險草稿與有限的已讀資料快取，並改善手機儲存列占用閱讀空間的問題。

## What Changes

- 第一階段：新增／編輯冒險紀錄自動保存本機草稿，包含表單及永久物品、消耗品、故事獎勵、休整活動等尚未完成明細，提供恢復及捨棄；角色與物品表單先不加入草稿。
- 草稿只在同一裝置與瀏覽器恢復，按帳號、角色、新增／編輯目標分開；保留未完成草稿至成功雲端儲存或玩家明確捨棄，不將草稿標示為正式紀錄。
- 恢復編輯草稿前先讀取完整雲端資料；雲端內容已不同時不整份套入，保留草稿供玩家取回文字並以最新雲端資料整理。無網路時可繼續已開啟表單的輸入，但不開放由舊副本啟動可提交的編輯表單。
- 完全離線重開時，在登入狀態仍有效且應用程式已可離線載入的前提下，提供同帳號草稿的唯讀查看／複製入口；連線取得完整最新資料後才提供恢復編輯。角色摘要讀取失敗不得擋住此入口。
- 第二階段：只快取已成功讀取的角色、冒險列表／完整詳情及倉庫資料，讓讀取暫時失敗時可查看副本，標示最後取得時間；線上開啟及返回前景時重新確認最新資料。
- 正式新增、修改、刪除與使用物品仍須雲端成功；不加入背景離線寫入佇列、自動重送或跨裝置草稿同步。
- 手機角色、冒險與物品表單的儲存／取消列留在表單末端隨內容捲動；錯誤提示仍靠近按鈕。此項已完成並驗證，草稿與已讀副本仍待實作。

## Capabilities

### New Capabilities

- `local-adventure-drafts`: 同裝置冒險草稿保存、恢復、清除、雲端內容比對與故障回饋。
- `local-read-cache`: 有限已讀副本、取得時間、雲端更新、權限隔離及異動失效。

### Modified Capabilities

- `mobile-pwa`: 將 `Reachable mobile adventure form actions` 的底部黏附改為文件流；同步 `Safe area and input ergonomics`，三種表單保留末端操作及安全區。

## Impact

前端新增小型 IndexedDB 儲存服務、草稿模型／冒險表單整合、已讀副本服務及各讀取頁狀態。沿用現有 RequestCache、角色異動通知、表單驗證與共用 FormFeedbackComponent，整合 AuthService 登出／切換的失效處理。調整共用手機操作列樣式及對應規格。

預期不變更後端 API、資料庫 schema 或依賴套件；不建立離線同步框架。雲端比對用完整已載入內容，不能僅依主記錄 updatedAt 推定子明細沒有變動。既有後端未提供原子版本比對，本 change 不宣稱解決所有同時寫入的競爭；正式跨裝置同時編輯控制需另立需求。

2026-10-12 使用者確認採用「本機草稿＋正式資料雲端同步」，不加入雲端草稿。此次補齊規劃，不修改程式、同步未實作的主規格、commit、push 或發布；先實作冒險草稿，再實作有限離線閱讀。已完成的操作列調整及其規格同步維持原狀。
