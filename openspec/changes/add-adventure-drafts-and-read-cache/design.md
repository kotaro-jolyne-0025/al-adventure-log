# Design

## Context

見 proposal.md。冒險表單的 FormGroup 與 gainedMagicItems、gainedConsumableItems、storyAwards、downtimeActivities、levelUp／catchup、classEntries 等 Signals 分開管理；不能只訂閱 valueChanges 就宣稱已保存完整草稿。loadEntry 透過完整讀取防護控制 detailsLoaded，buildSaveRequest 產生原子雲端儲存請求；草稿不是該 API 請求的重送佇列。

CharacterService、AdventureService 與 InventoryService 已透過 RequestCache 快取部分讀取，並以 characterChanged／cacheInvalidated 通知更新 HUD。現有 PWA 僅配置靜態 assetGroups，沒有個人 API 快取。手機冒險操作列黏附已取消，三種表單正常捲動已驗證；本次補齊草稿及快取規劃。

CharacterShell 的 router-outlet 目前包在成功取得角色資料的條件內，父層讀取失敗會阻擋子頁；authGuard 仍即時檢查登入期限。離線入口必須處理這兩項既有條件，不能僅新增 IndexedDB 後宣稱離線重開可用。2026-10-12 使用者確認採用本機草稿及正式資料雲端同步。

## Goals / Non-Goals

**Goals:** 依既有表單及快取失效機制提供可辨識、可恢復的本機輸入與唯讀副本；正式資料仍由雲端成功回應決定。階段一先完成冒險草稿與正常捲動操作列，階段二再加有限已讀副本。

**Non-Goals:** 不增加草稿雲端 API、角色／物品草稿、完整離線建角／編輯、背景同步佇列、整庫預下載或原子跨裝置版本鎖。不改現有每日帳號確認、登入期限及正式資源／快照商業規則。

## Decisions

### 1. 小型本機資料層

使用原生 IndexedDB，資料庫版本 1，分開 drafts 與 readCopies，公開少量 get／put／delete／clearScope 操作；每筆帶 schemaVersion、ownerId、characterId、key、savedAt。LocalStore 不注入 AuthService，帳號脈絡由呼叫端傳入，避免 AuthService → CharacterService → 本機層 → AuthService 的循環。localStorage 繼續只處理原有主題／排序／登入資訊。

選擇原因：草稿與明細為結構化資料，IndexedDB 具非同步及交易能力；不增加離線資料框架或套件。[MDN IndexedDB](https://developer.mozilla.org/en-US/docs/Web/API/IndexedDB_API) 說明其適用於較大量結構化資料。替代方案為 localStorage，但同步整份序列化與資料大小限制較不適合複雜冒險明細；API Service Worker 通用快取又難區分帳號、唯讀畫面與編輯資料用途。

### 2. 第一階段草稿鍵與內容

預設每帳號／角色保留一份新增草稿，每筆既有冒險保留一份編輯草稿。鍵為 ownerId + characterId + adventure:new／adventure:entryId；已存在草稿先讓玩家選擇恢復或捨棄，尚未選擇前不讓新的自動保存覆寫它。

保存可編輯欄位與全部明細 Signal 的原始值，包括空白名稱、null／空字串、未完成數量、同調、靈魂幣標記、獲得來源、故事獎勵、活動及升級輸入。日期保存 YYYY-MM-DD，還原為既有日期控制項需要的 Date。保存已有明細 ID 以保留歷史關聯，不保存 HTTP／驗證錯誤、isSaving、loading、computed 總計、Token 或登入憑證。新增草稿的舊資源基準僅可作背景資訊，恢復及正式提交用新取得的基準；編輯時保留舊減少資料，不重現已移除的永久物品資源卡。

初始化、程式回填及明細讀取完成前不啟動保存。完成後以規範化快照判斷實際輸入變更，約 1 秒停止輸入後保存；處理 FormGroup 與所有明細／升級 Signals，不能只依 form.dirty。返回列表及頁面進入背景時嘗試立即保存最新輸入；新輸入不因保存失敗而被還原。狀態只有在交易完成後才改成成功。

草稿不設定自動到期刪除；成功雲端儲存或玩家確認捨棄才清除。返回／取消既有編輯導覽仍保留草稿，「捨棄草稿」另提供明確操作。登出停止目前帳號待寫任務、隱藏草稿，保留已完成保存的草稿；同帳號登入後重新驗證目標再提供恢復，不在登入頁暴露草稿內容。

### 3. 恢復前核對雲端

每份編輯草稿保存從雲端載入時的原始可編輯快照，包括主記錄、休整活動、物品及故事獎勵；以固定欄位、明細 ID 與穩定順序正規化比對，不把列表回傳順序或格式化數字當成衝突。只比主記錄 updatedAt 不足以證明子明細沒變動，因此不用它作唯一判斷。

開啟表單先取得完整雲端資料，完成後再提供恢復。相同基底可套用玩家輸入並重新算衍生值；基底不同時保持最新雲端表單，草稿以唯讀的欄位名稱／值及複製文字入口供玩家取回，不能提供「直接整份覆蓋」捷徑。403／404 禁止套用或重建已刪除歷史；不讓本機草稿繞過 detailsLoaded。

區分兩種斷線情境：已在線上完整載入的表單可以繼續編輯並保存草稿；完全離線重開則僅提供唯讀查看／複製已保存草稿，不載入可編輯表單、不建立新冒險、不提供正式提交。第一階段就提供這個入口，不依賴第二階段的角色副本；角色摘要失敗時仍呈現目標的本機草稿入口與重試，不用假角色或空基準讓表單通過載入防護。重新連線不自動套用草稿，成功取得完整資料後仍由玩家選擇恢復。

離線重開須已登入同一帳號且 Token 尚未過期，並已在線上完成 Service Worker 與應用資源快取。首次離線造訪、瀏覽器清除資料或登入失效時不承諾可用；登入失效沿用登入出口，已保存草稿保留至同帳號重新登入，不延長登入期限或增加離線身分驗證。

正式提交前對恢復中的編輯草稿再做一次完整雲端比對；讀取失敗禁止此次提交但保留輸入。此為提早發現已發生的跨裝置異動，讀取後到寫入之間仍存在現有 API 的競爭窗口；不承諾原子樂觀鎖。替代方案是後端 revision／If-Match，需擴大 API 與交易邊界，留作另外需求。

雲端傳送成功後先停止自動保存、使該草稿的舊寫入失效，再刪除，防止導航前排隊的保存重新建回草稿。若清除本機失敗，顯示「雲端已儲存，本機草稿尚未清除」，不把雲端成功改成失敗；下次以雲端內容及提交完成標記辨識相同草稿並禁止再次自動提交。傳送中斷而結果未知時保留草稿且提示先檢查雲端紀錄，尤其新增紀錄，沒有自動重送。

### 4. 第二階段讀取副本

只覆蓋角色列表／摘要、冒險列表／完整詳情、倉庫列表，不保存冒險表單 defaults 作離線基準。讀取頁透過小型 facade 返回 data、source、fetchedAt、error；不把持久化 fallback 插進所有 getById／getDefaults，避免編輯端把副本當作成功載入。

父層角色摘要與子頁各自保留 source、fetchedAt 及錯誤狀態；讀取頁入口不能全部依賴角色雲端 GET 成功才呈現。角色有有效副本時可顯示帶時間的 HUD 與導覽；沒有摘要副本但有目標冒險／倉庫副本時，仍可閱讀該目標，摘要顯示無可用資料，不能顯示假的 0 或以子頁時間代表 HUD 時間。摘要與子頁任一仍為副本／未更新時，角色相關正式操作保持停用，直到所需最新資料全部成功取得。

線上首次開啟、從背景返回、恢復連線或手動刷新，以 forceRefresh 嘗試取得新資料，保留現有同目標進行中合併機制；沒有頁面操作時不另設輪詢。暫時錯誤才取有效副本，401／403／404 走現有安全及不存在流程。完整冒險詳情只在主記錄與所需子資料同次全部成功後存一份，不拼湊不同輪成功／失敗的半份詳情。

建議初始上限：副本從取得起保存 7 天，每帳號最多 100 個副本鍵，超出以最久未使用者淘汰；草稿使用不同 store，不參與副本淘汰。限制是本提案預設，不是瀏覽器或遊戲規則。副本模式的 HUD 及清單清楚顯示來源和取得時間，變更操作停用；網路恢復後等最新讀取成功才恢復，navigator.onLine 僅為重試觸發而非連線成功證明。

### 5. 擴充既有失效順序

LocalStore scope 有 session／character generation；登出、切換帳號或角色異動同步提高 generation，所有讀取及 pending put 在提交前檢查該 generation。先標為失效，再非同步刪除持久化副本，最後維持既有 HUD 通知順序；刪除若失敗，失效標記仍阻止舊副本被重新使用。登出清除該帳號 readCopies，草稿不視為雲端讀取快取。

同目標草稿以 revision 在讀寫交易比較，其他分頁版本不同時不覆蓋，保留本頁輸入並提供取回文字／重新載入；不引入多分頁合併框架。跨頁及登入切換的失效測試沿用現有 RequestCache regression 的晚到回應情境。

### 6. UI 與手機操作列

恢復提示放在冒險表單開頭正常文件流：顯示保存時間，使用既有 Material button 提供「恢復草稿」及次要「捨棄草稿」，捨棄用 MatDialog 確認，Escape 取消且返回觸發焦點。平時草稿保存狀態放在儲存區上方次要文字；失敗用既有 errorContainer／onErrorContainer 與 FormFeedbackComponent 的回復入口。文字使用「保存在此裝置，尚未儲存至雲端」，避免與既有雲端儲存成功 Snackbar 混淆。

冒險表單的黏附與重複覆寫已移除，保留末端布局、safe-area padding、錯誤定位、禁用條件與按鈕可換行增高；後續草稿提示維持三種表單正常捲動。新增提示不改既有欄位順序、搜尋間距或角色 HUD 排版，也不建立常駐全域草稿列。

唯讀副本以頁面內次要狀態顯示取得時間及「重新取得資料」按鈕，停用的正式操作提供文字原因。語意角色用 onSurfaceVariant／既有警示與錯誤 token，無額外硬編碼色。手機 320／360／390、桌機、深淺色及 200% 字級，提示自然換行；可及名稱、可見焦點、觸控區、鍵盤、單一有意義的 live 回饋均需驗收，自動保存每次成功不彈 Snackbar 或搶焦點。

## Risks / Trade-offs

- 手機作業系統突然終止 → 平時持續保存，[visibilitychange](https://developer.mozilla.org/en-US/docs/Web/API/Document/visibilitychange_event) 作輔助；不能只靠離開事件，也不承諾尚未完成交易的最後一秒輸入一定保留。
- 瀏覽器拒絕保存或清除資料 → 提供保存失敗及取回文字，不將本機草稿當備份；瀏覽器配額與淘汰行為參照 [MDN](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria)。
- 手機草稿不出現在電腦 → 草稿狀態說明只在此裝置；跑團結束需取得雲端成功才能回家接續。
- 副本資源已過時 → 對全部副本顯示時間及唯讀狀態，異動後失效，不以登入的 24 小時間隔控制正式資料更新。
- 存在 UI 復原與基底比對誤差 → 專用冒險 draft adapter、日期正規化及全明細回歸測試，不直接序列化 Angular 表單物件。

## Migration Plan

無後端 migration。初次使用建立本機 store，不匯入既有 Token 或把空表單轉為草稿。草稿資料具版本，相容版本保持，不相容版本只能取回文字與明確捨棄；readCopies 可失效後重新取得。應用程式更新沿用現有確認流程，不自動重新整理。

先完成階段一與手機排版驗收，再進行階段二；未完成階段二時不得同步其主規格或宣稱正式角色／冒險／倉庫資料可離線查看，第一階段僅提供本機草稿的唯讀取回。發布須另外依 VERSIONING.md 授權與驗證。回退時停止使用新的本機資料，不因部署回退自動清除草稿；舊版不提供恢復入口時如實說明。

離線重開驗收使用 production build 的本機靜態服務與隔離的模擬 API：先在線上等待 Service Worker 控制頁面並保存草稿／讀取副本，再切離線，重新整理、直接開啟深層網址及關閉頁籤後重開。開發模式未啟用 Service Worker，僅模擬 API 錯誤不能取代此驗收。第一階段驗證草稿唯讀入口不依賴角色摘要成功；第二階段另驗證父子副本、各自時間與操作停用。記錄 Token 過期、未快取資源及首次離線無資料的出口；三星瀏覽器實機驗證另記錄，不以 Chrome 模擬代替。

## UI 規劃自評

任務清楚、資訊層級、元件語意、token 一致、狀態回饋、表現克制各 2／2；自適應與無障礙各 1／2，待實作後以版面、鍵盤及實機驗證，非已完成的 UI 認證。
